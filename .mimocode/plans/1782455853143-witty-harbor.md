# Plan: Panel de Admin para Gestionar Tipos de Ausencia

## Objetivo

Crear una tabla configurable `AbsenceTypeConfig` en la BD y una página de admin dedicada donde se puedan:

- Ver todos los tipos de ausencia existentes
- Editar nombre, color, límite anual (días), y reglas (requiere justificante, necesita aprobación, cuenta para balance, descripción)
- Crear tipos nuevos
- Eliminar tipos no utilizados

## Problema actual

Los tipos de ausencia están hardcodeados en 3 capas (Prisma enum, Zod schema, frontend ABSENCE_TYPES). No hay forma de configurarlos desde la UI.

---

## Cambios por archivo

### 1. Database — `database/prisma/schema.prisma`

Añadir modelo `AbsenceTypeConfig`:

```prisma
model AbsenceTypeConfig {
  id                   String   @id @default(uuid())
  code                 String   @unique  // e.g. "VACATION", "SICK", "PERMISO_SINDICAL"
  name                 String              // Display name: "Vacaciones", "Baja médica"
  color                String   @default("#6366f1")  // Tailwind color hex
  icon                 String   @default("calendar") // lucide icon name
  description          String?
  annualLimitDays      Int?                  // null = sin límite
  countsForBalance     Boolean  @default(false) // ¿Descuenta del saldo anual?
  requiresAttachment   Boolean  @default(false) // ¿Requiere justificante?
  requiresApproval     Boolean  @default(true)  // ¿Necesita aprobación?
  isActive             Boolean  @default(true)
  createdAt            DateTime @default(now())
  updatedAt            DateTime @updatedAt

  @@index([isActive])
}
```

Luego: `npx prisma migrate dev --name add_absence_type_config`

### 2. Backend — Nuevo controlador + rutas

**Archivo nuevo: `backend/src/controllers/AbsenceTypeConfigController.ts`**

- `getAll` — GET /api/absence-types (listar todos, incluyendo inactivos para admin)
- `create` — POST /api/absence-types (crear nuevo tipo)
- `update` — PUT /api/absence-types/:id (editar tipo existente)
- `delete` — DELETE /api/absence-types/:id (solo si no hay vacaciones asociadas al código)

**Archivo nuevo: `backend/src/routes/absenceTypeConfigRoutes.ts`**

- CRUD routes con `protect` + `requireGlobalAdmin`

**Archivo nuevo: `backend/src/schemas/absenceTypeConfigSchemas.ts`**

- Zod schemas para create/update validation

### 3. Backend — Registro de rutas

**`backend/src/app/registerRoutes.ts`** — Añadir:

```ts
import absenceTypeConfigRoutes from '../routes/absenceTypeConfigRoutes';
// ...
app.use('/api/absence-types', protect, requireGlobalAdmin, absenceTypeConfigRoutes);
```

### 4. Backend — Seed de tipos iniciales

**`database/prisma/seed.ts`** — Añadir función `seedAbsenceTypeConfig()` que inserte los tipos actuales hardcodeados como registros en `AbsenceTypeConfig`, para que existan desde el primer momento.

### 5. Frontend — Página admin: `frontend/src/pages/AbsenceTypesPage.tsx`

- Tabla/card-list con todos los tipos de ausencia
- Botón "Nuevo tipo" que abre modal/formulario inline
- Cada fila: código, nombre, color (swatch), límite anual, toggles (justificante, aprobación, balance), acciones (editar, desactivar)
- Formulario crear/editar: campos para cada propiedad
- Confirmación antes de eliminar
- Patrón visual: seguir el patrón de `UserManagementProfilesTab.tsx` (tabla desktop + cards mobile, modal para crear/editar)

### 6. Frontend — Routing

**`frontend/src/App.tsx`** — Añadir:

```ts
const AbsenceTypesPage = lazy(() => import('./pages/AbsenceTypesPage'));
// ...
<Route path="/absence-types" element={<ProtectedRoute feature="settings"><AbsenceTypesPage /></ProtectedRoute>} />
```

### 7. Frontend — Sidebar

**`frontend/src/components/sidebarNavigation.tsx`** — Añadir al array `admin`:

```ts
{ path: '/absence-types', label: 'Tipos de Ausencia', icon: <Calendar size={18} />, feature: 'settings' }
```
