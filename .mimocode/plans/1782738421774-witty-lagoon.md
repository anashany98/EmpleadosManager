# Plan de implementación: Módulo de Obras para contabilizar horas, dietas, hospedaje y vuelos

> **Estado**: entrevista completada. Plan listo para revisión del usuario.

---

## 1. Resumen ejecutivo

Ampliar el modelo actual `Project` para convertirlo en una **Obra** de contabilidad analítica (horas + gastos por empleado), añadir un modelo polimórfico `ObraExpense` para dietas / hospedaje / vuelo / transporte, y un importador Excel para gastos que referencia la obra por su `code`. Las horas se siguen capturando vía `EmployeeProjectWork` (reutilizado) y opcionalmente desde la ficha del empleado. Permiso: solo **admin global** (igual que `Project` hoy).

---

## 2. Contexto del proyecto (descubierto)

- **Stack**: monorepo. `backend/` Express + Prisma + PostgreSQL + BullMQ + ExcelJS + Multer + S3; `frontend/` React + Vite + Tailwind + TanStack Query + xlsx; `database/prisma/schema.prisma`.
- **Permisos**: `checkPermission('<feature>','read'|'write')` y `requireGlobalAdmin`. La feature `projects` ya existe (ProjectController, projectRoutes, EmployeeProjectWorkController, employeeProjectWorkRoutes).
- **Importación Excel patrón**: `PayrollBatchController.upload` → `ExcelParser.parseBuffer` → `MappingService.applyMapping` → `PayrollRow` + `AccountingEntry`. Lo replicaremos.
- **Frontend rutas**: declaradas en `frontend/src/App.tsx` con `<ProtectedRoute feature="...">`; sidebar en `frontend/src/components/sidebarNavigation.tsx`; cliente HTTP en `frontend/src/api/client.ts`; toaster `sonner`.
- **Almacenamiento**: `StorageService` (S3-compat) para buffers subidos; multer configurado en `backend/src/config/multer`.

### 4.2 Nuevo `ObraExpense` (gastos polimórficos)

```prisma
model ObraExpense {
  id           String   @id @default(uuid())
  obraId       String
  employeeId   String?
  type         String   // PER_DIEM | LODGING | FLIGHT | TRANSPORT | OTHER
  date         DateTime
  amount       Decimal  @db.Decimal(15, 2)
  currency     String   @default("EUR")
  description  String?
  vendor       String?
  reference    String?
  origin       String?  // para FLIGHT/TRANSPORT
  destination  String?  // para FLIGHT/TRANSPORT
  receiptUrl   String?
  status       String   @default("APPROVED") // PENDING | APPROVED | REJECTED
  importBatchId String?
  createdById  String
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt

  obra         Project @relation(fields: [obraId], references: [id], onDelete: Cascade)
  employee     Employee? @relation(fields: [employeeId], references: [id], onDelete: SetNull)
  importBatch  ObraImportBatch? @relation(fields: [importBatchId], references: [id], onDelete: SetNull)

  @@index([obraId, type])
  @@index([obraId, date])

  @@index([status])
```

## 5. Backend — nuevos ficheros

### 5.1 Rutas y controllers

- **`backend/src/routes/obraRoutes.ts`**: CRUD de obras.
  - `GET /api/obras` (listado paginado, filtro `status`, `q`)
  - `GET /api/obras/:id` (detalle con totales: horas, gastos por tipo)
  - `POST /api/obras` (crear — validar `code` único, `status` default `ACTIVE`)
  - `PATCH /api/obras/:id` (actualizar; rechaza edición si `status=INACTIVE` salvo `status`/correcciones)
  - `POST /api/obras/:id/close` (INACTIVE; bloquea altas)
  - `POST /api/obras/:id/reopen` (ACTIVE)
  - `GET /api/obras/:id/totals` (resumen agregado por tipo)
- **`backend/src/routes/obraExpenseRoutes.ts`**:
  - `GET /api/obras/:id/expenses` (listado paginado por obra + filtros)
  - `POST /api/obras/:id/expenses` (alta manual; rechaza si `obra.status=INACTIVE`)
  - `PATCH /api/expenses/:id` (corrección)
  - `DELETE /api/expenses/:id` (soft via status o hard según política)
- **`backend/src/routes/obraImportRoutes.ts`** (multer `.xlsx/.xls/.csv`):
  - `POST /api/obras/imports/upload` (sube archivo, crea `ObraImportBatch`, guarda en `StorageService`)
  - `POST /api/obras/imports/:id/map` (aplica mappingRules → genera preview + warnings)
  - `POST /api/obras/imports/:id/commit` (persiste `ObraExpense` válidas; deja inválidas en `warnings`)
  - `GET /api/obras/imports` (listado de batches recientes)

### 5.2 Controllers

- `backend/src/controllers/ObraController.ts` — usa `prisma.project.*`, `AuditService.logWithContext`, `ApiResponse`.
- `backend/src/controllers/ObraExpenseController.ts` — usa `prisma.obraExpense.*`.
- `backend/src/controllers/ObraImportController.ts` — sigue el patrón de `PayrollBatchController.upload`/`applyMapping`:
  1. Recibe archivo con multer.
  2. Llama `ExcelParser.getHeaders(buffer)` y crea batch `UPLOADED`.
  3. Sube buffer con `StorageService.saveBuffer({ folder: 'obras/imports/<batchId>', ... })`.
  4. En `applyMapping` → `ExcelParser.parseBuffer` + `ObraImportService.applyMapping(rules)`:
     - Por fila: busca `Project` por `code` (`ObraImportService.findObraByCode`); si no existe → warning `OBRA_NOT_FOUND`.
     - Valida `amount > 0` y `type ∈ {PER_DIEM, LODGING, FLIGHT, TRANSPORT, OTHER}`; type desconocido → warning `INVALID_TYPE`.
     - Valida `date` parseable; si no → warning `INVALID_DATE`.
     - Persiste válidas con `prisma.obraExpense.createMany`.
     - Actualiza `ObraImportBatch.status='COMMITTED'`, `resultSummary=JSON({inserted, warnings})`.
- `backend/src/services/ObraImportService.ts` — lógica de mapeo fila a fila, separado del controller para poder testearlo aislado.
- `backend/src/services/ObraReportService.ts` — agrega gastos/horas por obra, exporta Excel (reutiliza `ExcelService` ya existente).

## 7. Formato del Excel (a documentar para el usuario)

Cabeceras esperadas (orden libre, configurable vía mapping):

| Columna        | Tipo   | Obligatorio | Notas                                                     |
| -------------- | ------ | ----------- | --------------------------------------------------------- |
| `obra_code`    | string | sí          | referencia a `Project.code`                               |
| `employee_dni` | string | no          | si está vacío, queda sin empleado                         |
| `type`         | enum   | sí          | `PER_DIEM` / `LODGING` / `FLIGHT` / `TRANSPORT` / `OTHER` |
| `date`         | fecha  | sí          | `dd/mm/yyyy` o serial Excel                               |
| `amount`       | número | sí          | > 0                                                       |
| `currency`     | string | no          | default `EUR`                                             |
| `description`  | string | no          |                                                           |
| `vendor`       | string | no          |                                                           |
| `reference`    | string | no          | nº factura, localizador, etc.                             |
| `origin`       | string | no          | para `FLIGHT`/`TRANSPORT`                                 |
| `destination`  | string | no          | para `FLIGHT`/`TRANSPORT`                                 |

Si `obra_code` no existe → fila a `warnings` con motivo `OBRA_NOT_FOUND`. Las válidas se insertan. Se puede reintentar el commit tras corregir/crear la obra.

### Manual (UI)

1. **Crear obra**: ir a `/obras`, "Nueva obra" → `code=OB-001`, `name=Reforma Nave Industrial`, `clientName=ACME`, `startDate=2026-07-01`, `budget=50000`, `managerId=<empleable>`, `status=ACTIVE`. Confirmar.
2. **Imputar horas**: en `EmployeeDetail` del empleado X → "Imputaciones a obras" → añadir 8h en OB-001 el 2026-07-15.
3. **Añadir gasto manual**: en `/obras/OB-001` tab "Gastos" → "+ Dieta" → importe 30 €, fecha 2026-07-15.
4. **Importar Excel de vuelos**: `/obras/imports` → wizard:
   - Subir `vuelos_julio.xlsx` con 3 filas: 2 con `obra_code=OB-001`, 1 con `obra_code=OB-999` (inexistente).
   - Mapear columnas (auto-detect si cabeceras coinciden).
   - Preview: 2 filas OK, 1 fila en `warnings` con motivo `OBRA_NOT_FOUND`.
   - Commit. Verificar `ObraExpense` count = 2, batch `status=COMMITTED`, `resultSummary` con `inserted:2, warnings:1`.
5. **Cerrar obra**: en `/obras/OB-001` → "Cerrar" → intentar alta manual → debe rechazar con mensaje "Obra cerrada".
6. **Reabrir**: "Reabrir" → `status=ACTIVE` → altas vuelven a funcionar.
7. **Reporte**: `/reports` → "Gastos por obra" → filtrar OB-001 + julio 2026 → "Exportar Excel" → descarga `.xlsx` con totales por tipo.
